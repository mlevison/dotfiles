+## 2026-07-22 — Course workbooks hosted on the APR site (off Dropbox)
+
+**Why.** Some clients' corporate firewalls block Dropbox but treat
+`agilepainrelief.com` as a normal business site, so attendees couldn't open
+their workbooks (this surfaced right before a CSPO cohort). The content is
+low-sensitivity reference material, so a real auth gate was overkill.
+
+**What we did.**
+- **Serve workbooks as static PDFs under `public/materials/`**, guarded by an
+  unguessable per-course slug (`<course>-<year>-q<quarter>-<16 hex>`, the hex from
+  `openssl rand -hex 8`) plus `X-Robots-Tag: noindex, nofollow` on `/materials/*`
+  in `netlify.toml`. Deliberately **not** in `robots.txt` (a `Disallow` would stop
+  crawlers fetching the file, so they'd never see the `noindex` — the two are in
+  tension) and not in the sitemap (bare `public/` files never enter it). Rejected a
+  real auth gate as disproportionate; recorded in `docs/adr/0001-...`. Chose a new
+  `/materials/` prefix over reusing `/downloads/` to keep public lead magnets and
+  private client workbooks in separate namespaces.
+- **Added a quarterly-updated variable for the workbook link.** The post-course
+  email carries two separate links: `{{var:training_folder}}` (the per-cohort mural
+  export, still on Dropbox, left alone) and the course workbook (previously a
+  hardcoded Dropbox folder in the template body). The workbook link now resolves via
+  `deriveWorkbookUrl()` (`email-automation/src/course-config.ts`) from
+  `courses/workbook-urls.json[type]` — a single source of truth, updated once per
+  quarter when the slug rotates — with an optional per-cohort `workbookUrl` override.
+  Returns null for courses not yet migrated (their template keeps its hardcoded link).
+- **Wired into all three CSPO emails.** The workbook link is `{{var:workbook_link}}`
+  in `pre-7day-cspo.html`, `pre-2day-cspo.html` (the "Download the Digital Workbook"
+  link — the pre-class, firewall-critical one), and `post-cspo.md`. The old links
+  pointed at Dropbox *folders* holding the workbook plus other artifacts that were
+  "not always up to date"; we deliberately point at just the single, current
+  `CSPO Workbook.pdf` and reworded the "files in this Dropbox folder" prose to suit.
+- **Fail-loud reachability check.** For any email (pre or post) whose template
+  references `{{var:workbook_link}}`, the send (including `--dry-run`) requires a
+  configured URL and `assertWorkbookReachable()` HEADs it, aborting on a non-200 —
+  catching a typo'd slug, an unpushed folder, or a filename mismatch before a student
+  is emailed a dead link. Scoped to APR-hosted `/materials/` URLs. Proves the link is
+  live, not that it's current.
+- **CSM/CSD** still hardcode their Dropbox workbook links; `deriveWorkbookUrl` returns
+  null for them, so nothing breaks. Migrating each: host its PDF under `/materials/`,
+  add a line to `workbook-urls.json`, switch its templates to `{{var:workbook_link}}`.
+- **Fixed a latent substitution bug (post-course markdown path).** `marked` runs
+  before variable substitution and percent-encodes the braces of any `{{var:...}}`
+  that sits in a link URL (`href="%7B%7Bvar:...%7D%7D"`), so the later regex never
+  matched — every URL-position variable shipped unsubstituted. This had silently
+  broken the murals `{{var:training_folder}}` link in every post email (it's only

+  `renderMarkdownEmail`, decode `%7B%7B`/`%7D%7D` back to braces before substituting.
+  The pre-course HTML templates are unaffected (no `marked` step).

+
+/** HEAD the URL; fall back to a 1-byte ranged GET if HEAD is refused. Returns 0 on network failure. */
+async function workbookUrlStatus(url: string): Promise<number> {
+  try {
+    const head = await fetch(url, { method: "HEAD" });
+    if (head.status !== 405 && head.status !== 501) return head.status;
+  } catch {
+    // fall through to a ranged GET
+  }
+  try {
+    const get = await fetch(url, { method: "GET", headers: { Range: "bytes=0-0" } });
+    return get.status === 206 ? 200 : get.status; // 206 Partial Content also means the file is served
+  } catch {
+    return 0;
+  }
+}
+
+/**
+ * Verify the workbook URL is live before anyone is emailed it. Scoped to
+ * APR-hosted /materials/ links (the hand-pasted random slug is the fragile bit);
+ * legacy Dropbox links are skipped since they don't answer HEAD reliably.
+ * Throws on a non-200 so the caller can abort the send. Note: this proves the
+ * link is live, not that it's the right (current) workbook.
+ */
+export async function assertWorkbookReachable(url: string): Promise<void> {
+  if (!/^https:\/\/agilepainrelief\.com\/materials\//.test(url)) {
+    console.log(`Skipping reachability check for non-materials workbook URL: ${url}`);
+    return;
+  }
+  const status = await workbookUrlStatus(url);
+  if (status !== 200) {
+    throw new Error(`Workbook URL is unreachable (HTTP ${status || "no response"}): ${url}`);
+  }
+  console.log(`Workbook URL OK (200): ${url}`);
+}
